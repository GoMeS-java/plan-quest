# «Заклятие Кошмара»: безопасный тест на Android

Дата: 31 октября 2026. Версия игры: **0.57**, рабочая ветка `citadel-development-20261030`.

**Тестовый адрес:** https://nightmare-android-test-20261031.choicecalf260.chatgpt.site

Это отдельная приватная среда. Если появился экран «Войдите, чтобы получить доступ», нажмите «Продолжить через ChatGPT» и используйте свой аккаунт владельца этого проекта. Это вход на тестовый сайт, а не подключение игры к Google-таблице.

Вверху игры должна быть полоса **«ТЕСТОВАЯ ВЕРСИЯ · Отдельные сохранения»**, а в меню — версия 0.57 и сообщение об отключённом Google. Основное приложение и его данные не обновляются этим адресом. Новый адрес сначала открывается без вашего прогресса — это ожидаемо.

## 1. Сначала сохраните настоящий прогресс

1. Откройте привычную, основную игру. Не удаляйте её и не очищайте данные браузера.
2. Если есть несинхронизированные изменения, при наличии сети вручную завершите синхронизацию. Если показана ошибка или конфликт, сначала сохраните доступные копии; не заменяйте данные наугад.
3. Если в меню есть **«СОХРАНИТЬ РЕЗЕРВНУЮ КОПИЮ»**, нажмите её. Через приложение «Файлы» проверьте, что в «Загрузках» действительно появился JSON-файл ненулевого размера. Сделайте ещё одну копию файла в отдельной папке. Сохраните снимки экрана ранга, ресурсов, последних заданий и улучшений для сравнения.
4. В старой основной версии из текущей main кнопки скачивания JSON ещё нет. В таком случае откройте свою таблицу `plan-data` в Google Таблицах, через меню файла выберите **«Создать копию»** и назовите её, например, `plan-data — резерв до Android-теста`. Проверьте, что открывается отдельная копия с данными. Если доступно, сохраните её дополнительно как Excel через «Поделиться и экспорт».
5. Копия таблицы сохраняет только уже синхронизированные данные. Если старое приложение не может синхронизироваться и не умеет экспортировать JSON, сохранность свежих локальных изменений пока не подтверждена. Оставьте его установленным и тестируйте новый адрес с пустым профилем; не переносите и не сбрасывайте основной профиль.

Excel/CSV из Google Таблиц не является JSON-копией игры. Не выбирайте такой файл в восстановлении. Самостоятельно менять расширение файла не нужно.

## 2. Откройте тестовую игру

1. На Android откройте ссылку выше в обычном **Chrome**, вне встроенного окна Telegram или другого приложения. Не используйте режим инкогнито.
2. При необходимости войдите через ChatGPT как владелец сайта.
3. Проверьте тестовую полосу и версию в меню **«ТЕСТ»**. Кнопка Google должна быть недоступна. Если видите привычную игру без тестовой полосы, не продолжайте этот тест на таком адресе.
4. Для проверки нового игрока ничего не импортируйте. Для проверки существующего прогресса, если у вас есть JSON из пункта 1, откройте **«ТЕСТ» → «ВОССТАНОВИТЬ КОПИЮ ИЗ ФАЙЛА»**, выберите копию и подтвердите. Это заменит только тестовый профиль. Дождитесь сообщения о сохранении и сравните показатели со снимками основной игры.

## 3. Установите отдельный значок

В меню Chrome ⋮ выберите **«Добавить на главный экран» / «Установить приложение»**. Название должно содержать **«Кошмар ТЕСТ»**. Запустите этот значок и снова проверьте тестовую полосу. Старый значок оставьте на месте. Если Chrome предлагает только обычный ярлык или установка не проходит, запишите это как результат проверки PWA, не считайте установку подтверждённой.

На телефон не нужны Node.js, Python или Git.

## 4. Проверьте обычные действия

Отметьте одно задание, введите шаги и выйдите из поля ввода, добавьте спонтанное дело. Откройте «Хронику», остальные игровые вкладки и раздел добычи. Закройте тестовую игру и откройте снова: значения должны остаться. Проверьте клавиатуру, прокрутку, поворот экрана, возврат из фона и системную кнопку «Назад». Сделайте снимок любого зависания, исчезновения прогресса или перекрытого элемента.

## 5. Проверьте Цитадель и жителей

Раскройте Цитадель, войдите в доступные комнаты, нажмите на предмет и перейдите через дверь в соседнее помещение. Если в перенесённой копии хватает ранга и ресурсов, улучшите одну комнату, запишите остаток до и после, перезапустите игру и убедитесь, что оплата была одна. Повторное нажатие не должно повторно оплачивать уже купленную ступень; при недостатке средств покупка должна быть отклонена.

Поговорите с доступным жителем, завершите разговор, начните другой. Проверьте переход к связанному разделу. Около смены часа понаблюдайте за перемещением и поговорите с жителем рядом с комнатой: когда он уходит, разговор у комнаты должен закрыться. Ночью и при низком ранге некоторые жители недоступны — это само по себе не ошибка. Часы телефона ради теста переводить не нужно.

## 6. Проверьте офлайн

Сначала откройте тест с интернетом. Затем включите авиарежим и убедитесь, что Wi-Fi тоже выключен. Перезапустите тестовый значок, отметьте задание и, если хватает ресурсов, улучшите комнату. Ещё раз закройте и откройте тест: изменения и одна оплата должны сохраниться. Верните интернет и проверьте те же значения. В этой сборке данные не отправляются в Google ни при возвращении сети, ни при ручном вызове синхронизации.

## 7. Проверьте копию и восстановление

В тестовой игре скачайте новую резервную копию. Затем измените одно задание и запомните изменение. Через **«ВОССТАНОВИТЬ КОПИЮ ИЗ ФАЙЛА»** выберите скачанный тестовый JSON. После подтверждения должны вернуться значения из файла; проверьте их ещё раз после перезапуска. Меню также позволяет скачать копию до последней замены. Не очищайте данные Chrome для этой проверки.

## 8. Google и обновление: отдельная проверка перед релизом

**В текущей тестовой сборке Google намеренно отключён. Настоящий OAuth здесь ещё не проверен.** Не пытайтесь подключать основной аккаунт и основную таблицу обходными способами. Настройщик должен сначала выполнить отдельную настройку ниже.

После неё используйте отдельный тестовый Google-аккаунт без основной таблицы: войдите, проверьте создание `plan-data-android-test`, синхронизируйте одну отметку, перезапустите приложение и проверьте значения. Проверьте повторный вход после выхода и после истечения доступа, офлайн-изменение и отправку после возвращения сети. На двух тестовых устройствах меняйте данные последовательно. При конфликте сначала скачайте **обе** предложенные копии, сравните их и только потом выбирайте нужные данные. Параллельные расходы на двух устройствах текущий протокол гарантированно безопасными не делает.

Обновление установленной PWA на настоящем Android также ещё не подтверждено. Для этой проверки настройщик должен выложить следующую проверенную сборку на **тот же тестовый адрес**. Перед нажатием «ОБНОВИТЬ» скачайте JSON. После обновления проверьте все значения, наличие копии до обновления и офлайн-запуск. Сейчас нельзя утверждать, что этот шаг выполнен только потому, что установилась 0.57.

## 9. Если что-то пошло не так

Закройте тест и откройте старый, привычный значок основной игры. Основную версию не заменяли, поэтому откатывать её файлы не нужно. Не импортируйте тестовый прогресс в основную игру. Не удаляйте Chrome и не очищайте данные сайтов. Сохраните тестовый JSON, снимок ошибки, модель телефона, версию Android/Chrome и короткое описание последнего действия. Если сама основная игра показывает другие значения, остановите синхронизацию и сравните сохранённые копии до любых замен.

## Настройщику: как включить только тестовый Google

Владелец выполняет внешнюю настройку; в этом цикле Google Cloud и основная таблица не изменялись.

1. Создать **отдельный проект Google Cloud** для теста. Не редактировать production OAuth и его список адресов.
2. В новом проекте включить Google Drive API и Google Sheets API. Настроить экран согласия в режиме Testing и добавить отдельный тестовый Google-аккаунт в тестовые пользователи.
3. Создать OAuth Client ID типа Web application. В Authorized JavaScript origins добавить ровно `https://nightmare-android-test-20261031.choicecalf260.chatgpt.site`, без пути и завершающего слеша. Приложение использует GIS token client; callback/redirect URL в коде не применяется. Не придумывать redirect URL для этого потока.
4. В `src/config.test.js` установить новый публичный `clientId`, `allowedOrigin` из пункта 3 и `cloudEnabled: true`. Сохранить `testMode: true`, `fileName: 'plan-data-android-test'` и запрет production Client ID. Секрет OAuth-клиента и токены в код не добавлять. `src/config.js` не менять.
5. Собрать `python build.py --test`, повторить проверки и обновить только отдельный тестовый Site. Для OAuth-проверок использовать отдельный аккаунт. Не переносить в тестовое хранилище метаданные входа, OAuth-токены или ID основной таблицы.
6. Проверить реальный вход и создание отдельной таблицы прежде, чем снимать блокировку релиза. Автоматические ответы API доказательством реального OAuth не являются.

Для разработчика: `python test_app.py` запускает обе сборки и весь синтетический набор. Параметр `CHROMIUM_EXECUTABLE_PATH` позволяет использовать установленный Chromium. Исходники тестового Site находятся в отдельном репозитории Sites; его сборка соответствует исходникам рабочей ветки, но production-игру он не заменяет.
