# Древо Судьбы · технический план для 1.5

«Древо Судьбы» показывает, какие действия продвинули игрока и что требуется для следующего узла. Это отдельный экран профиля. Круглый «Путь Восхождения» по-прежнему читает `cfg/ascension` и хранит собственные открытия. В 1.4.1 новый экран и записи прогрессии отсутствуют.

## Источники прогресса

| Ветвь | Источник | Как считать |
| --- | --- | --- |
| Тело | `per/*` для повторений и тренировок, `days/*` для шагов, `weights/*` для журнала веса | Использовать существующие агрегаты профиля. Один подход учитывается по сохранённой записи, вес оценивается по серии замеров за согласованный период. |
| Воля | `days/*`, `weeks/*`, история редакций `forge-tasks/*`, `chains/*` и `cfg/chains-discoveries` | Считать отметки по действовавшему на дату расписанию. Брать серии и достижения «Разрыва Оков» из его модели. |
| Разум | Отметки обучения в `days/*`, сохранённые пользовательские задания и их редакции в `forge-tasks/*` | Начать с явно зафиксированных занятий. Для новых навыков сначала определить явный признак записи, например категорию задания. |
| Путь | Завершённые `goals/*`, цели Кузницы в `forge-tasks/*`, явные отметки личных этапов | Связать один этап с одним постоянным идентификатором цели. Читать значение и порог через действующие расчёты целей. |
| Цитадель | Подтверждённые улучшения `buys/*`, коллекция достижений, сохранённый ранг | Читать результат существующей прогрессии и показывать действия, которыми игрок его заработал. |

Перед добавлением узлов вынести общие расчёты из профиля и `src/realm-achievements.js` в чистые функции. Существующие формулы, границы игровых суток и обработку старых записей покрыть регрессиями до переноса. Использовать стабильные идентификаторы фактов и сохранять связь узла с источником. Редактирование одной записи пересчитывает её вклад, повторная синхронизация учитывает тот же вклад один раз.

## Данные и выпуск

1. Утвердить состав узлов, пороги, правила для изменённых и удалённых записей. Для первых испытаний вычислять прогресс из сохранения при открытии экрана. Проверить одни и те же синтетические профили с разным порядком записей, часами устройства и наборами старых полей.
2. Если игре нужны необратимые открытия, использовать отдельный документ `cfg/fate-tree` со схемой версии 1. Хранить подтверждения по ID узла, предусмотреть слияние без потери открытий и включить новый документ в проверки обновления, резервной копии и обмена между устройствами. Черновики и прогнозы вычислять по фактам.
3. Проверить баланс на сохранениях новичка и опытного игрока. На первом этапе дерево показывает прогресс и визуальные открытия. Любые будущие награды требуют отдельных порогов и правил выдачи. Источником осколков и штрафов остаётся действующий расчёт Цитадели.
4. Собрать отдельную сцену с крупным тёмным древом, цепями и постепенно подсвечивающимися узлами. Предусмотреть управление масштабом и перемещением пальцами, список узлов для доступности и режим с уменьшенной анимацией. Проверить оба дерева на одном профиле, затем открыть сцену в установленной Android PWA без сети.
