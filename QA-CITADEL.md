# Проверка интегрированной «Цитадели Спящего»

Дата: 30 октября 2026. Ветка: `citadel-development-20261030`. Версия: `0.55`.
Базовая версия для сравнения исходной экономики и прогресса: `c65a44e`.

## Реализовано в текущем цикле

- Каждая существующая комната имеет три уровня обустройства. Две платные ступени меняют интерьер: балдахин, письменный стол, дополнительные стеллажи, звёздная сфера, наковальня и оформление зала. Улучшения отражаются и на разрезе замка.
- Стоимость и необходимый ранг показаны до покупки. Расходуется существующий запас ядер души, общий с «Воспоминаниями». Новая валюта, опыт или источники наград не добавлены.
- Уровень комнаты выводится из оплаченной записи в `buys`, без отдельного изменяемого счётчика. Идентификатор покупки постоянен для комнаты и ступени. Покупка, оплата и результат фиксируются одной записью общего сохранения; повторный запрос той же ступени не списывает ядра.
- Локальные транзакции повторно читают сохранённый снимок и проверяют исходный расчёт доступных ядер до записи. В Chromium Web Locks сериализует покупки и записи между вкладками. При отказе сохранения улучшение и расход не применяются. Существующий магазин также повторно проверяет остаток, срок ожидания и корзину в одной транзакции.
- Жители отображаются в комнатах и меняют местоположение и занятие утром, днём, вечером и ночью. Реплики учитывают существующие ежедневные задачи, испытание, недельный английский, запас ядер и обустройство мастерской. Из разговора можно найти жителя и перейти к заданиям или хронике.
- В интерьерах появились записи по назначению комнаты: дневные дела, недельная хроника, испытание, спонтанные дела, глобальные цели и экипировка. Это представления исходного состояния с переходами в существующие разделы.
- Интерьеры получили своды, витражи, ковры, очаги, дополнительные предметы и освещение по времени суток. Сохранены общий персонаж, экипировка, оформление, управление с клавиатуры и режим уменьшенного движения.
- Исправлено подтверждение синхронизации при записи во время медленной отправки в Sheets: новая запись остаётся ожидающей и отправляется автоматически следующим запросом. Индикатор синхронизации обновляется после завершения запроса.

## Запуск

Нужны Python с Pillow, Node.js 22+ и история Git с базовым коммитом.

```sh
python build.py
npm ci
npx playwright install --with-deps chromium
npm test
```

Для уже установленного совместимого Chromium используется `CHROMIUM_EXECUTABLE_PATH`. Локально тесты выполнены с `CHROMIUM_EXECUTABLE_PATH=/tmp/chromium`. `TEST_FILTER` позволяет повторить конкретную группу по регулярному выражению; заключительный прогон выполнен без фильтра. Ожидания быстрых записей привязаны к завершению очереди и наблюдаемому состоянию, а не к фиксированным 60 мс.

## Оставшиеся ограничения

- Android проверен сенсорной эмуляцией Chromium. Физический телефон, установка на домашний экран, системный возврат, экранная клавиатура и iOS/Safari отдельно не проверялись.
- Google OAuth и Sheets проверены с тестовыми ответами API, включая задержанный запрос. Реальный вход и синхронизация с личной таблицей не выполнялись.
- Web Locks защищает покупки между вкладками одного браузера. Общий серверный арбитраж расходов между двумя одновременно офлайн-устройствами отсутствует: раздельные покупки на этих устройствах могут превысить общий запас после слияния. Постоянный идентификатор защищает повтор той же комнаты и ступени, но не резервирует ядра для разных покупок на разных устройствах. Эта возможность требует отдельного решения для координации устройств.
- В браузерах без Web Locks остаётся однопоточная транзакция в пределах страницы; межвкладочная защита там не подтверждена.
- Синхронизация оформления сохраняет прежнюю модель: побеждает более новая запись документа. Одновременное офлайн-редактирование оформления не объединяется по отдельным комнатам.
- Этот цикл реализует улучшения существующих комнат. Строительство новых этажей, свободная планировка и непрерывное перемещение жителей по маршрутам пока не интегрированы. Распорядок жителей меняет комнату по времени, без симуляции пути между комнатами.
- `test_app.py` — прежний ручной сценарий, требующий внешнего `seed.json`; он не запускался. Автоматический набор `tests/citadel.mjs` не требует личных данных и не изменяет исходники во время проверки.

Основные формулы начислений, штрафов и ранга, существующие механики и закрытые игровые каталоги не изменялись. Расход ядер за улучшение — новая явная покупка в прежней экономике. Скрытый контент в отчёт и диагностические сообщения набора не включается.
