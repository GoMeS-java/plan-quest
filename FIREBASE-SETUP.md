# «Нерушимая память: финал» · Подключение Firebase

Ветка 1.3.6 содержит клиент Firebase Auth, серверные правила Realtime Database
и планировщик FCM. В обычной сборке Firebase выключен до настройки владельцем.
Существующий Google Sheets работает при отсутствии активной настройки Firebase.
Изолированный ZIP продолжает работать с отдельным локальным профилем без Google.

## Что подготовить в консоли владельца

1. Откройте существующий Firebase-проект владельца или зарегистрируйте тестовый
   проект в Firebase Console, если его ещё нет. Работайте только с синтетическими
   данными и отдельным HTTPS-доменом до проверки. Другой путь на том же
   домене использует то же локальное хранилище, что и рабочая игра.
2. В **Authentication → Sign-in method** включите Google и выберите адрес
   поддержки. В **Authentication → Settings → Authorized domains** добавьте
   домен тестового PWA без схемы и пути. Зарегистрируйте веб-приложение в
   **Project settings → Your apps** и скопируйте его публичную конфигурацию.
   Включайте только нужный провайдер.
3. Создайте Realtime Database по умолчанию в закрытом режиме. Скопируйте URL конкретной
   базы из консоли. Используйте отдельную тестовую базу, поскольку публикация
   правил заменяет правила существующей базы.
4. С Node.js 22 и Java 21 запустите `npm run test:cloud-rules`. Команда
   использует демо-проект и локальные Auth/Database эмуляторы. Для публикации
   в выбранный тестовый проект выполните `npx firebase-tools@15.35.0 login`,
   затем `npx firebase-tools@15.35.0 deploy --only database --project PROJECT_ID`.
   Сверьте идентификатор проекта перед командой.
5. В отдельной сборке для этого адреса добавьте блок из
   [cloud/config.example.js](cloud/config.example.js) в `src/config.js`.
   Подставьте публичную конфигурацию, укажите точный HTTPS origin и включите
   `enabled`. Оставьте `vapidKey` пустым до проверки Push. Команда
   `python build.py` собирает эту конфигурацию в `docs/`.
   OAuth client secret и сервисные ключи не включаются в сборку.
6. Для GitHub Pages используйте `authMode: 'popup'`. Если Android блокирует
   всплывающее окно, тестируйте вход в Chrome. Для редиректа нужен origin,
   который сам обслуживает Firebase `/__/auth/`, например Firebase Hosting
   того же проекта. При таком размещении укажите этот домен в `authDomain`
   и выберите `authMode: 'redirect'`.

## Первая синхронизация и восстановление

В «Аккаунт и сохранения» войдите через Google, затем явно включите
синхронизацию профиля. Первая отправка возможна после записи и чтения
защитной локальной копии. При одинаковых версиях повторная отправка
пропускается. После разрыва сети очередь определяется по текущему локальному
снимку и последней подтверждённой версии. Две расходящиеся версии сохраняются
локально и требуют выбора. Для передачи из Sheets сначала скачайте и проверьте
JSON с нужного устройства. Автоматического переноса таблицы в Firebase нет.

Каждая облачная запись меняет один снимок целиком с проверкой номера версии.
Три предыдущие версии хранятся отдельно от текущей внутри защищённого профиля.
Локальная история и ручной JSON доступны отдельно от облака. Если локальный
снимок превышает 2 МиБ, отправка останавливается. Правила доступа разрешают
доступ к снимкам и подпискам только владельцу с соответствующим UID.

## Подключение фонового Push

1. Откройте согласованный тестовый проект Firebase с синтетическими данными.
   Запишите его идентификатор, HTTPS-адрес приложения и полный URL Realtime
   Database. Проверьте тариф проекта. Для публикации функций и планировщика
   нужен Blaze, переход на него согласуйте с владельцем.
2. Из корня репозитория, под учётной записью владельца стенда, выполните
   `npx firebase-tools@15.35.0 functions:list --project PROJECT_ID`.
   Сверьте имена `sendCitadelReminders` и `sendCitadelTestPush` со списком.
   Если нужна установка или обновление на согласованном стенде, выполните
   `npm --prefix cloud/functions ci`, затем
   `npx firebase-tools@15.35.0 deploy --only functions:sendCitadelReminders,functions:sendCitadelTestPush --project PROJECT_ID`.
   При запросе параметра `VKACH_DATABASE_URL` укажите URL базы из шага 1.
   Функция использует учётную запись выполнения проекта и должна иметь доступ
   к этой базе и право отправки FCM.
3. В **Project settings → Cloud Messaging → Web Push certificates**
   скопируйте публичный VAPID-ключ. Добавьте его в `vapidKey` конфигурации
   стенда. Используйте веб-конфигурацию этого же проекта, точный HTTPS-origin
   стенда и разрешённый домен Google-входа. Соберите и откройте PWA на стенде.
4. Войдите тестовым Google-аккаунтом и дождитесь синхронизации. Включите Push
   и дождитесь статуса «Устройство зарегистрировано в Firebase». Нажмите
   «Отправить тест» и проверьте, что карточка появилась в уведомлениях Android.
   Затем сохраните расписание и проверьте плановую доставку при закрытом PWA.

В игре откройте «Настройки → Фоновые уведомления». Расписание хранится в
обычном приватном сохранении, а согласие на доставку действует только на
устройстве, где его выдали. Кнопка «Отправить тест» обращается к FCM через
функцию с проверкой аккаунта. Принятие запроса Firebase и появление карточки
в системных уведомлениях проверяются отдельно.

Планировщик сверяет номер синхронизированного снимка, часовой пояс и часы
тишины. Для дел дня нужна отметка актуального дня о незавершённых делах.
Дневник питания проверяется по сохранённым приёмам пищи и записи дня.
Напоминание «Разрыв Оков» предлагает открыть текущий лимит в игре, а итоги
недели приходят по воскресеньям. Уведомления о достижениях используют
сохранённые отметины Цитадели и отголоски легенд после включения категории. На экране блокировки
используются общие тексты без результатов, лимитов и названий достижений.

При проверке на Samsung используйте синтетическое сохранение. Проверьте
тестовую отправку, плановое уведомление с закрытым PWA, подавление после
сохранённого выполнения, потерю и восстановление сети, смену часового
пояса, часы тишины, отзыв разрешения, выход, вход в другой аккаунт и
переустановку PWA. После смены пояса откройте игру онлайн, чтобы обновить
подписку. Устаревшая или отозванная подписка должна пропускать доставку.
Проверьте запуск планировщика и время последнего успешного вызова в
Cloud Scheduler. Настройки GitHub Pages не включают Firebase по умолчанию.

По актуальной таблице тарифов Spark для Realtime Database включает
100 одновременных соединений, 1 ГБ хранения и 10 ГБ скачивания в месяц.
В Blaze расходы зависят от трафика и выполнения планировщика.
